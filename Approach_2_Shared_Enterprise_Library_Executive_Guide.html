The Enterprise Challenge: 36+ Microservice Sprawl
  • Dependency Drift & CVE Chaos: 36 repos maintain unpinned or drifting versions of Flask, requests, and urllib3. A single zero-day CVE triggers 36 emergency PRs.
  • Boilerplate Copy-Paste Sprawl: Every microservice reinvents JSON logging, custom exception handling, and Prometheus/actuator metrics.
  • Audit & Security Vulnerabilities: Without unified regex filters, unmasked PII (credit cards, auth tokens) slips into centralized logging tools (Splunk/ELK).
  • Observability Fragmentation: Inconsistent correlation IDs (`X-Correlation-ID`) cause broken distributed traces across inter-service calls.
The Solution: Shared Enterprise Core Library
  • Centralized Bill of Materials (BOM): 1 single setup.py pins tested, hardened dependencies. Microservices inherit all transitive packages automatically.
  • Single-Line Microservice Bootstrapping: Standard functions configure logging, unified error handlers, latency timers, and actuator probes in seconds.
  • Guaranteed PII Masking: Automated regex sanitizes sensitive cardholder, personal, and auth headers before emission.
  • Dual Docker Compose Architecture: Full flexibility to build locally with secrets isolated or pull pre-compiled images with zero build friction.

01 Structured Logs & PII Masking

Automated Regex Scrubbing:
• Credit Cards: \b(?:\d[ -]*?){13,16}\b ➔ [REDACTED_CC]
• SSNs: \b\d{3}-\d{2}-\d{4}\b ➔ [REDACTED_SSN]
• Bearer Tokens: Bearer [A-Za-z0-9\-_\.]+ ➔ Bearer [REDACTED_TOKEN]

Traps EnterpriseBaseException, HTTP 400/404/500, and unhandled tracebacks into RFC 7807 JSON:

Microservice Bootstrap Refactoring (Exchange Service app.py)

Notice how 200+ lines of redundant middleware, logging configurations, and error handlers collapse into clean helper invocations: 

from flask import Flask
from enterprise_core import (
    setup_enterprise_logging, register_enterprise_error_handlers,
    register_latency_interceptors, create_actuator_blueprint, register_swagger_ui
)

def create_app():
    app = Flask(__name__)
    context_path = "/currency-exchange-service-python"

    # 1. PII-Masking JSON Logger | 2. Unified RFC 7807 Error Envelope
    logger = setup_enterprise_logging(app, app_name="currency-exchange-service-python")
    register_enterprise_error_handlers(app, default_prefix="CESP")

    # 3. Microsecond Latency & Correlation ID Interceptor
    register_latency_interceptors(app, service_name="currency-exchange-service-python")

    # 4. K8s Actuator Probes (/health/liveness, /health/readiness, /info, /metrics)
    actuator_bp = create_actuator_blueprint(service_name="currency-exchange-service-python", version="1.0.0", context_path=context_path)
    app.register_blueprint(actuator_bp, url_prefix=context_path)

    # 5. OpenAPI Specification & Swagger UI
    from e2e.route.swagger_doc import OPENAPI_SPEC
    register_swagger_ui(app, context_path=context_path, openapi_spec_dict=OPENAPI_SPEC)

    # 6. Mount Domain Business Routes
    from e2e.route.exchange_routes import exchange_bp
    app.register_blueprint(exchange_bp, url_prefix=context_path)
    return app

CONTAINER SECURITY

Hardened Multi-Stage Docker Architecture with Secret Isolation

Page 6
Stage 1 Ephemeral Builder (Secret Isolation)

Compiles virtual environment with Git authentication; discards tokens immediately: 

FROM python:3.12-slim AS builder
WORKDIR /build

# 1. Ephemeral Build-Time Secret
ARG GITHUB_TOKEN

RUN apt-get update && apt-get install -y --no-install-recommends \
    git build-essential curl && rm -rf /var/lib/apt/lists/*

RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

COPY requirements.txt .
# 2. Inject token into git URL config only for pip install
RUN if [ -n "$GITHUB_TOKEN" ]; then \
      git config --global url."https://${GITHUB_TOKEN}@github.com/".insteadOf "https://github.com/"; \
    fi && \
    pip install --upgrade pip && \
    pip install --no-cache-dir -r requirements.txt
Zero-Trust Guarantee: ARG GITHUB_TOKEN exists only inside the temporary builder layer and is completely excluded from the runner image.
Stage 2 Hardened Non-Root Production Runtime

Executes as unprivileged non-root user (UID 10001) with minimal attack surface: 

FROM python:3.12-slim AS runner
WORKDIR /app

# 1. Create Dedicated Non-Root User (UID: 10001)
RUN groupadd -g 10001 appgroup && \
    useradd -u 10001 -g appgroup -s /bin/sh -m appuser

# 2. Copy compiled venv and application code
COPY --from=builder /opt/venv /opt/venv
COPY --chown=appuser:appgroup . /app

ENV PATH="/opt/venv/bin:$PATH" \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

# 3. Enforce Unprivileged Execution
USER 10001

CMD ["gunicorn", "--bind", "0.0.0.0:8000", "--workers", "2", "app:app"]
Hardened Defense-in-Depth: Non-root execution blocks container breakout exploits. Compilers (gcc, git) are stripped from the production image.

Operational Dimension Workflow A: Local Build & Push (docker-compose.build.yml) Workflow B: Zero-Build Remote Pull (docker-compose.pull.yml)
Primary Target Persona Core library developers, platform architects. QA engineers, frontend devs, CI/CD smoke test runners.
Local Build Requirements Docker BuildKit, ARG GITHUB_TOKEN, Python source files. None! Zero compilers, zero tokens, zero local source needed.

DEVOPS AUTOMATION

Automated Orchestration via build-and-push-docker.ps1

Page 8
Single-Entrypoint Orchestration: The root PowerShell orchestrator build-and-push-docker.ps1 normalizes registry authentication, token validation, image compilation, registry pushing, and container lifecycle across both Compose configurations.
-Action BuildPushRun (Default Production Mode) 
.\build-and-push-docker.ps1 -Action BuildPushRun
  • Authenticates to Docker Hub using DOCKER_USERNAME and DOCKER_PASSWORD.
  • Passes READ_PACKAGES_TOKEN / GITHUB_TOKEN securely as build arguments.
  • Builds container images using docker-compose.build.yml.
  • Pushes certified images to hub.docker.com/u/${DOCKER_USERNAME}.
  • Launches containers on Docker Desktop in detached mode (-d).
-Action PullAndRun (Zero-Build QA Mode) 
.\build-and-push-docker.ps1 -Action PullAndRun
  • Authenticates to Docker Hub registry.
  • Pulls latest verified images using docker-compose.pull.yml.
  • Requires ZERO local source compilation and NO Git access tokens.
  • Spins up complete microservice mesh instantly for integration testing.
-Action BuildAndPush (CI Runner Mode) 
.\build-and-push-docker.ps1 -Action BuildAndPush
  • Compiles images and pushes them to Docker Hub.
  • Does NOT start local container runtime (ideal for automated CI pipelines).
-Action Down (Teardown & Cleanup) 
.\build-and-push-docker.ps1 -Action Down
  • Gracefully stops running containers across both build and pull configurations.
  • Removes Docker bridge network (currency-mesh) and releases port 8000 & 8100.
Environment Variable Required For Purpose & Example Value
DOCKER_USERNAME Build & Push, Pull Docker Hub registry namespace (e.g. amsidhlokhande). Defaults to amsidhlokhande.
DOCKER_PASSWORD Automated Docker Login Docker Hub Personal Access Token (PAT) or account password.
READ_PACKAGES_TOKEN / GITHUB_TOKEN Workflow A Build GitHub PAT with read:packages scope to clone enterprise-core-python in multi-stage builder.
